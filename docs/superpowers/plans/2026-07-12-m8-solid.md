# M8 "Solid" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the shipped snap the artifact the user stands behind publicly: lean, feature-complete (semantic search works), verifiable on the production NVR without mutation, with real `/logs` content — proven by a VM gate plus a 3–7 day production field-soak.

**Architecture:** Three lanes on one branch (`feat/m8-solid`): the artifact (R4 sqlite fix → evidence-driven size pass → svc trim → prime pruning), the harness (a new `--nvr-safe` non-purging mode + stash-guard fix), and docs/upstream (tee-parity `/logs`, detect-fps guidance, Docker repro of the hot-add KeyError). One PR at the end (Launchpad builds take hours; one CI build cycle). Exit = VM gate green on the lean artifact + production soak.

**Tech Stack:** snapcraft 9 / core26 / strict; POSIX sh + bash (tee-parity scripts only); python 3.11 (source-built part); LXD (local builds AND the gate VM); GitHub Actions → Launchpad remote-build → Snap Store.

**Spec:** `docs/superpowers/specs/2026-07-12-m8-solid-design.md` (approved 2026-07-12).

## Global Constraints

- **No Frigate behavior patches** — `spike/patches/0001-env-driven-paths.patch` remains the ONLY Frigate-source patch (snapcraft.yaml comment l.374–379 records the ruling).
- **Upstream-parity principle (governs every size decision):** a `config.yml` valid on upstream Docker v0.17.2 must work in the snap. If upstream's amd64 image ships a component (an ffmpeg tree, tensorflow for classification training, both opencv stacks), we ship it too — the size lead is dropped and RECORDED, never forced. This is the go2rtc-bridge lesson generalized.
- **The production host is off-limits for mutation.** No `snap remove/install`, no config regeneration, no `snap set` round-trips, no cert swaps, no service restarts caused by us on the host. Full gates run in an LXD VM; the host only ever runs `--nvr-safe`. The one exception: the user-executed store-tracking refresh in Task 10.
- **LXD single-builder rule:** exactly one `snapcraft pack` at a time. Builds and gates run FOREGROUND in a single Bash call with `timeout: 600000` — never backgrounded.
- **Secrets discipline:** no credential in argv, committed files, or evidence. The harness scrubber + zero-creds gate (spike-smoke.sh L42–46, L1440–1441) must stay green; any new evidence capture follows capture-minimization (`jq keys`, `del(...)` on credential-bearing fields).
- **Render-once config ownership:** nothing in this milestone may rewrite an existing operator `config.yml` outside the harness's existing stash/restore blocks.
- **All M0–M7 assertions preserved** unless a task deliberately retires one; every retirement is named in the task and recorded in findings.
- **Line-number anchors** in this plan refer to `main` at `d383ae1`; they drift as tasks land — re-locate by the quoted content, not the number.
- **Evidence classes** ([TRANSCRIPT]/[REPORT]/[STORE/CI]/[FIELD]) tag every number in `docs/m8-findings.md`.
- Branch: `feat/m8-solid` off `main`. Commit per step; conventional prefixes (`feat:`, `fix:`, `test:`, `docs:`, `chore:`).
